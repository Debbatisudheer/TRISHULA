# TRISHULA V0.9.98 — Real-Time WebSocket Gateway

## Objective

Establish the persistent WebSocket transport boundary for Mission Control clients without yet coupling domain telemetry/event publication to the socket layer. Domain-specific live streaming is reserved for V0.9.99+.

## Endpoint

`GET /v1/mission-control/ws`

The endpoint requires a standard WebSocket upgrade and returns HTTP 101 on success.

## Protocol

- WebSocket text frames
- Protocol identifier: `trishula-ws-v1`
- Gateway version: `v0.9.98`
- Server-to-client welcome message: `mission_control.websocket.connected`
- Server supports client ping/pong and close handling.
- Client application messages are intentionally ignored in V0.9.98.

## Architecture

```text
Mission Control Client
        │
        │ WebSocket
        ▼
Mission Control WebSocket Gateway
        │
        ├── connection registry
        ├── upgrade / handshake
        ├── text-frame transport
        ├── ping/pong
        └── broadcast boundary
                │
                ▼
       V0.9.99+ live publishers
```

`PublishJSON` is the controlled broadcast boundary. V0.9.98 does not automatically publish Kafka/telemetry events; that integration belongs to later milestones.

## Compatibility

Existing REST APIs, Kafka, Redis, PostgreSQL, command orchestration, scheduling, reconciliation, and DLQ paths remain unchanged.

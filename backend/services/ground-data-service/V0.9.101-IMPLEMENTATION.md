# TRISHULA V0.9.101 — Mission Control Alerts & Notifications

## Scope

V0.9.101 extends the verified V0.9.100 Mission Control real-time channel with a normalized alert projection and read-only alert query API. Existing telemetry and command execution streams remain unchanged.

## Real-time flow

`Ground Event -> Kafka -> Kafka Consumer -> Alert Manager -> WebSocket Gateway -> Mission Control`

## Alert rules

- INFO events do not create alerts.
- WARNING, ERROR, and CRITICAL events create/update an alert.
- ACTIVE events are represented as `ACTIVE`.
- ACKNOWLEDGED events are represented as `ACKNOWLEDGED`.
- Recovery/CLEARED events clear the referenced alert key.
- Alert identity is deterministic from the event record or referenced fault key.

## WebSocket message

Type: `mission_control.alert`

Stream version: `v0.9.101`

Protocol: `trishula-ws-v1`

## HTTP API

`GET /v1/mission-control/alerts`

Optional query parameter:

`mission_id=TRISHULA`

The response exposes alert version, active count, total count, and the normalized alert list.

## Compatibility

- `mission_control.telemetry` remains stream version `v0.9.99`.
- `mission_control.command_execution` remains stream version `v0.9.100`.
- WebSocket gateway/API contract version advances to `v0.9.101`.
- V0.9.100 functionality is preserved.

# TRISHULA V0.9.108.1 — Command Scheduler Min-Heap DSA Optimization

## Baseline

V0.9.107.1 — Ground ingestion queue pressure observability.

## Real project problem

The ground-data-service command scheduler already maintained scheduled commands in a map. On every polling tick, `dispatchDue()` called `List("")`, which copied pending schedules and sorted the entire list by `ScheduledAt` before scanning for due work.

That means the scheduler repeatedly paid an `O(n log n)` sorting cost even when only the earliest scheduled command was needed.

## DSA improvement

The scheduler now maintains a min-heap ordered by:

1. `ScheduledAt`
2. `ScheduleID` as a deterministic tie-breaker

The dispatch loop inspects the heap head to find the next candidate and removes stale entries lazily when schedules have been cancelled, dispatched, expired, or otherwise become non-pending.

### Complexity change

Previous due-dispatch selection:

```text
map of schedules
      ↓
copy to slice
      ↓
sort by ScheduledAt
      ↓
scan
```

Typical selection cost per polling tick: `O(n log n)`.

New selection path:

```text
pending schedules
      ↓
min-heap
      ↓
heap[0] = earliest pending schedule
```

Inspection of the next schedule is `O(1)` and insertion/removal is `O(log n)`. A polling tick with no due command no longer sorts the entire schedule set.

`List()` intentionally keeps its sorted output behavior because API consumers expect chronological listing. The optimization is specifically for the internal dispatch path.

## Behavioral preservation

No command lifecycle states were changed.

Preserved:

- schedule creation validation
- duplicate command protection
- cancellation
- persistence
- dispatch behavior
- expiration/error handling
- chronological `List()` API ordering
- snapshot fields
- lazy recovery from stale heap entries

## Tests added

`command_scheduler_heap_test.go` verifies:

- scheduled-time heap ordering
- deterministic same-time tie breaking
- stale cancelled-entry removal

## Scope

This checkpoint changes only the ground command scheduler's internal scheduling data structure. No spacecraft physics, rover navigation, science processing, communication model, Kafka contract, database schema, or Mission Control UI behavior is changed.

## Optional algorithm comparison benchmark

The package also contains `command_scheduler_heap_benchmark_test.go`, which compares the scheduler's heap-based selection against the previous full-slice sorting approach over 10,000 schedules. The benchmark is diagnostic only; it is not used to claim a fixed speedup across machines.

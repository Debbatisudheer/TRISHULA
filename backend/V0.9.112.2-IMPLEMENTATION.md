# TRISHULA V0.9.112.2 — Ground Mission Runtime Control

## Scope

This milestone connects the validated C++ physical mission runtime controller to the Go Ground Data Service without introducing UI-only mission state.

## Runtime control

- `GET /v1/missions/{missionID}/runtime`
- `POST /v1/missions/{missionID}/runtime/start`
- `POST /v1/missions/{missionID}/runtime/pause`
- `POST /v1/missions/{missionID}/runtime/resume`
- `POST /v1/missions/{missionID}/runtime/abort`
- `POST /v1/missions/{missionID}/runtime/reset`

The Ground service starts `trishula_physical_mission_runtime_bridge.exe` and sends START/PAUSE/RESUME/ABORT/RESET/STEP commands to the persistent C++ runtime process.

While the physical runtime reports RUNNING, the Ground service advances it at a one-second control interval. Each successful physical step is converted into physical telemetry records and ingested through the existing Ground `Service.Ingest()` path, preserving PostgreSQL/Kafka/Redis processing.

Pause stops the STEP calls. Resume continues the same C++ physical state. Abort prevents further physical stepping.

## Important qualification

This milestone is a software runtime-control integration. It does not claim real spacecraft hardware, RF, flight software certification, or flight safety certification.

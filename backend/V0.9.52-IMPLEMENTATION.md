# TRISHULA V0.9.52 — Ground Command Ingestion & Validation Pipeline

## Purpose
Harden and formalize the ground command-ingestion boundary introduced by the preceding ground/spacecraft command work. V0.9.52 establishes a deterministic boundary between received command packets and commands eligible for execution.

## Contract
- Accept only `GroundPacketType::Command` packets.
- Parse `command_id`, `target`, `opcode`, and optional `parameters`.
- Normalize target/opcode identifiers.
- Validate identifiers, allowed targets, and allowed opcodes.
- Reject duplicate command IDs.
- Reject out-of-order sequence numbers per command stream.
- Enforce command archive capacity.
- Preserve command fields after encoded frame decode.
- Keep telemetry packets outside the command-ingestion boundary.

## Physical integrity
V0.9.52 performs validation only. It does not create or mutate spacecraft physical state. Physical actuation remains owned by the existing command execution / spacecraft command link layers.

## Regression
The existing V0.9.52 ingestion campaign plus the new command-ingestion contract campaign must pass alongside all previous TRISHULA regressions.

# TRISHULA V0.9.54 — Vehicle Command Adapter Layer

## Purpose

V0.9.54 formalizes the boundary between validated ground commands and the physical vehicle model. The existing rover adapter is retained and hardened so malformed numeric command parameters cannot partially advance physical state.

## Additive changes

- Promoted the Vehicle Command Adapter as the V0.9.54 ground-to-vehicle boundary.
- Kept START_ROVER, DRIVE, and STOP_ROVER mapped to the existing physical SurfaceRover model.
- Made numeric parameter parsing strict: `std::stod` must consume the complete numeric token.
- Rejects malformed values such as `x=25m` before calling the physical rover step.
- Added a dedicated V0.9.54 safety regression campaign.
- Preserved V0.9.53 acknowledgement and operational feedback behavior.

## Physical integrity rule

```text
Ground command
  -> validation
  -> vehicle adapter
  -> physical preconditions
  -> physical rover model
  -> state change
```

If command parameters are invalid, the physical model is not advanced and the physical step counter remains unchanged.

## Local validation

The complete local regression is expected to contain the previous 52 tests plus the V0.9.54 safety campaign: 53 tests total.

Windows/UCRT64 verification remains the authoritative project acceptance step.

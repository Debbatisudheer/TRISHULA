# TRISHULA V0.9.106.1 — Ground Ingestion Queue DSA Optimization

## Baseline

- Starting checkpoint: **V0.9.105.1 — Autonomous Surface Mission Completion**.
- The existing 55-test suite passed before this change.
- No physics, GNC, rover navigation, science generation, relay semantics, mission-state authority, or UI behavior was intentionally changed.

## Real production problem identified

The ground telemetry, event, and command ingestion pipelines stored their FIFO archives in `std::vector` and removed the oldest element with:

```cpp
archive_.erase(archive_.begin());
```

Front erasure from a vector is O(n) because remaining elements must be shifted. These archives are explicitly consumed as FIFO queues by `pop_record`, `pop_event`, and `pop_command`.

## DSA solution

Replace the FIFO archive container with `std::deque`.

- append at the back: amortized O(1)
- remove from the front: O(1)
- preserve FIFO ordering
- bounded archive capacity remains unchanged
- duplicate/order/current-state maps remain unchanged

Affected pipelines:

1. `TelemetryIngestionPipeline`
2. `EventIngestionPipeline`
3. `CommandIngestionPipeline`

## Why this is a real TRISHULA improvement

This is a data-structure correction based on the actual access pattern. It does not change the physical simulation or manufacture any mission behavior.

The ground ingestion layer can receive sustained telemetry/event/command streams. Therefore, avoiding O(n) front deletion removes an unnecessary queue-management cost as archive occupancy grows.

## Validation

Added `trishula_dsa_ground_ingestion_queue` to verify FIFO behavior for all three pipelines.

Added `trishula_dsa_ground_ingestion_queue_benchmark` for empirical enqueue/dequeue measurement.

The benchmark is informational and does not use timing as a correctness assertion.

# TRISHULA V0.9.113.1 — Spacecraft Subsystem Status Foundation

## Scope
Adds backend-owned spacecraft subsystem status to the existing physical runtime without changing the validated START/PAUSE/RESUME/ABORT semantics.

## Real sources
- Power: modeled battery state driven by elapsed physical runtime and propulsion/RCS load.
- Propulsion: actual `SimulationEngine::last_propulsion_output()` firing state, thrust fraction, and remaining propellant derived from spacecraft mass.
- Thermal: modeled temperature state driven by actual propulsion/RCS activity with cooling.
- Communication: derived from actual physical telemetry sequence generation (`LOCKED` after telemetry exists).
- Navigation: derived from finite physical position/speed state.
- Health: deterministic aggregation of modeled power/thermal/navigation health.

## Ground
Runtime bridge protocol now carries these values and runtime telemetry records persist them through Ground ingestion. Runtime API version is `v0.9.113.1`.

## UI
Mission Control should read these fields from runtime/telemetry and must not synthesize values locally.

## Qualification
This is a software physical mission simulation subsystem model, not a flight-certified spacecraft EPS/thermal/RF implementation.

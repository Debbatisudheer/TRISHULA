# TRISHULA Mission Control UI V0.4

## Purpose
V0.4 is the physical-mission integration step for the Mission Control UI. It builds on the verified V0.3.1 UI and does not modify the V0.9.105 Go backend.

## Key rule
The mission visualization no longer advances spacecraft/rover position with a synthetic timer. When physical position telemetry (`x_m`, `y_m`) is available, the surface trajectory is plotted from the actual telemetry history. Mission phase is taken from an explicit `mission_phase`/`phase` telemetry field when supplied, with the existing `SURFACE_READY` mode mapped to Surface Operations. If physical phase data is absent, the UI does not invent a moving spacecraft.

## Data path
C++ physical mission -> ground telemetry -> V0.9.105 REST/WebSocket -> Next.js UI.

## Scope
- physical telemetry-driven visualization
- real rover position history projection when available
- physical mission runtime metadata panel
- latest record/sequence/mission timestamp visibility
- no backend changes
- no synthetic trajectory playback

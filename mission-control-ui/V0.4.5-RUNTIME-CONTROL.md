# TRISHULA Mission Control UI V0.4.5 — Physical Runtime Control

## Scope

V0.4.5 integrates the validated Ground physical runtime API from V0.9.112.2 into the existing V0.4.4 Mission Control UI.

The UI is a control surface only. It does not advance, pause, resume, abort, or simulate mission state locally.

## Runtime API

- `GET /v1/missions/{missionID}/runtime`
- `POST /v1/missions/{missionID}/runtime/start`
- `POST /v1/missions/{missionID}/runtime/pause`
- `POST /v1/missions/{missionID}/runtime/resume`
- `POST /v1/missions/{missionID}/runtime/abort`
- `POST /v1/missions/{missionID}/runtime/reset`

The existing Next.js Ground API catch-all proxy is used, so the browser calls `/api/ground/...` when `NEXT_PUBLIC_GROUND_API_URL` is not overridden.

## Lifecycle controls

- `START`: enables the backend physical runtime.
- `PAUSE`: stops physical stepping while preserving the current physical state.
- `RESUME`: continues from the preserved physical state.
- `ABORT`: stops physical stepping and leaves the runtime aborted.
- `RESET`: requests the backend runtime reset from terminal state to ready state.

Button enablement is derived from the backend runtime snapshot. No local state machine is used to manufacture mission status.

## Runtime telemetry

The UI polls the runtime snapshot every second and displays backend-owned values including:

- runtime state
- control sequence
- telemetry sequence
- mission time
- physical phase
- altitude
- speed
- runtime version

The existing mission telemetry polling and WebSocket remain unchanged.

## Visualization integrity

The old `playing` UI-only visualization control was removed. The mission visualization now receives physical telemetry only. No synthetic timer-based movement is introduced by V0.4.5.
